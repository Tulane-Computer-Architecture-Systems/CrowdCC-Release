# CrowdCC: corruption benchmark for crowd counting

Implementation of **CrowdCC: Jointly Benchmarking Corruption Robustness and Deployment Quantization in Crowd Counting** by S Mahmudul Hasan and Lu Peng (*IEEE/CVF Winter Conference on Applications of Computer Vision (WACV), 2027*).

CrowdCC applies 23 corruptions in six families, each at three severity levels, to the test splits of ShanghaiTech A/B, UCF-QNRF, and JHU-Crowd++. Seven corruptions alter head annotations to account for occlusion, cropping, warping, or coverage.

## Corruptions

| family | corruptions |
|---|---|
| `sensor_exposure` | `gaussian_noise`, `low_light`, `highlight_clipping_bloom`, `fixed_pattern_sensor_noise`, `vignetting_lens_shading` |
| `optics_motion` | `camera_motion_blur`, `far_field_defocus`&dagger;, `lens_contamination`\*, `lens_flare_veiling` |
| `environment` | `rain_streaks`, `snow_particles`, `depth_aware_haze`&dagger;, `cast_shadow_illumination` |
| `encoding_resolution` | `h264_crf_compression`, `packet_loss_concealment`\*, `moire_aliasing`, `spacing_resolution_loss` |
| `scene_clutter` | `crowd_like_distractors`\*, `object_distractors`\*, `texture_distractors` |
| `visibility_loss` | `structured_foreground_occlusion`\*, `fov_loss_camera_reaim`\*, `viewpoint_perspective_shift`\* |

\* Alters annotations. &dagger; Requires depth maps generated by `crowdcc depth`.

See [the corruption parameters](docs/corruptions.md) or run `crowdcc list --json` for all severity settings.

## Installation

```bash
git clone https://github.com/Tulane-Computer-Architecture-Systems/CrowdCC-Release
cd CrowdCC-Release
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-lock.txt
pip install -e .
crowdcc list
```

Python 3.10 or newer is required. The reference environment uses Python 3.13.9 on Linux x86_64 with packages pinned in `requirements-lock.txt`. PyAV supplies bundled FFmpeg codecs.

**Depth maps.** `depth_aware_haze` and `far_field_defocus` use per-image depth maps from [Depth Anything 3](https://github.com/ByteDance-Seed/depth-anything-3), generated by `crowdcc depth` on a CUDA GPU. Install the pinned depth dependencies (PyTorch 2.12.1 and Depth Anything 3 commit `3fe327a`):

```bash
pip install --ignore-requires-python -r requirements-depth.txt
```

On Python 3.13.9, `--ignore-requires-python` bypasses the pinned commit's declared `requires-python <= 3.13.0` limit. The reference checkpoint, `depth-anything/DA3-GIANT-1.1`, is licensed CC BY-NC 4.0 (non-commercial). That license applies to the checkpoint and its depth maps, not the CrowdCC code. To skip both depth-dependent corruptions, use `--exclude depth_aware_haze,far_field_defocus`.

## Datasets

Download datasets from their authors and retain their original directory layouts:

| `--dataset` | dataset | `--root` | test split |
|---|---|---|---|
| `sha` | ShanghaiTech Part A | `.../ShanghaiTech/part_A` | `test_data/images`, `test_data/ground-truth` |
| `shb` | ShanghaiTech Part B | `.../ShanghaiTech/part_B` | `test_data/images`, `test_data/ground-truth` |
| `qnrf` | UCF-QNRF | `.../UCF-QNRF_ECCV18` | `Test/` (images and `*_ann.mat`) |
| `jhu` | JHU-Crowd++ v2.0 | `.../jhu_crowd_v2.0` | `test/images`, `test/gt` |

The full test splits contain 182 (SHA), 316 (SHB), 334 (QNRF), and 1,600 (JHU) labeled images.

**Custom datasets.** Provide one `<image stem>.json` file per image with head coordinates as `[[x, y], ...]` or `{"points": [[x, y], ...]}`. Use `--dataset <name> --images <dir> --annotations <dir>`. Head coordinates are required because several corruptions use median head spacing to determine their strength.

## Generation

For a CPU smoke test, apply light Gaussian noise to ten images:

```bash
crowdcc generate --dataset sha --root /data/ShanghaiTech/part_A \
  --out ./crowdcc_verification --corruption gaussian_noise --levels light --sample 10 --workers 1
```

For the full benchmark:

```bash
OUT=./crowdcc_data

# Generate depth maps once per dataset (GPU).
crowdcc depth --dataset sha --root /data/ShanghaiTech/part_A --out $OUT

# Generate all 23 corruptions at three severity levels.
crowdcc generate --dataset sha --root /data/ShanghaiTech/part_A --out $OUT --workers 16
```

Repeat for `shb`, `qnrf`, and `jhu`. Useful options:

- `--corruption <name|family|altering|all>`, `--exclude <names>`, `--levels light,high`: select corruptions and severity levels.
- `--sample N`: sample N images per corruption across the density range.
- `--estimate-only`: estimate disk usage; `--dry-run`: show the plan without writing files.

Interrupted runs can resume. Existing outputs are reused when input hashes, seed, parameters, and output hashes match the manifest; otherwise, they are regenerated. Failures are recorded in the run report. Failures before writing leave no files, while post-write verification failures retain the image and annotation for inspection.

HSR measurement errors are logged as `hsr_error` in the per-image manifest and counted as `n_hsr_errors` in the run summary without stopping generation. Use `--overwrite` to refresh cached images and metrics after changes to measurement code.

Output layout:

```text
<out>/<dataset>/test/<corruption>/<level>/<image_id>.png          lossless PNG
<out>/<dataset>/test/<corruption>/gt/<level>/<image_id>.gt.json   per-image annotation
<out>/<dataset>/test/<corruption>/manifest.json                   parameters, seeds, hashes
```

A full run produces 69 corrupted images per source image at its original resolution.

## Evaluation

**1. Predictions.** Create a CSV with one row per clean or corrupted image:

```csv
corruption,level,image_id,count
clean,,IMG_1,171.3
gaussian_noise,light,IMG_1,169.8
...
```

[`examples/predict.py`](examples/predict.py) generates this CSV using a Python function that maps an RGB `uint8` image of shape `(H, W, 3)` to a count. For a pipeline test without a trained model, use the brightness-based example `--model examples.mean_count:count`.

```bash
python examples/predict.py --benchmark $OUT/sha/test \
  --dataset sha --root /data/ShanghaiTech/part_A \
  --model my_model:count --out preds.csv
```

**2. Scoring.**

```bash
crowdcc evaluate --benchmark $OUT/sha/test --predictions preds.csv --report report.json
```

Example output:

```text
clean       : MAE 67.41   RMSE 110.67
mcMAE       : 87.25   (mcRMSE 144.10)
RD          : +29.4%
mCE         : 1.000   vs CSRNet, sha, fp32 (packaged)
...per family and per corruption tables...
```

Corrupted images are scored against `n_kept` in their `.gt.json` files; clean images use `n_original`. The metrics are:

- **Cell MAE:** Mean absolute error for corruption $c$ at severity $s$. For the seven annotation-altering corruptions, $\mathrm{MAE}^{\mathrm{kept}} = \mathrm{MAE}/(1-f_{\mathrm{drop}})$.
- **$E_c$:** Mean of $\mathrm{MAE}^{\mathrm{kept}}$ over the three severity levels.
- **mcMAE:** Mean of $E_c$ over all 23 corruptions.
- **RD (relative degradation):** $100\,(\mathrm{mcMAE}-E_\varnothing)/E_\varnothing$, where $E_\varnothing$ is clean MAE.
- **mCE:** Mean of $E_c/E_c^{\mathrm{CSRNet}}$ across corruptions, following ImageNet-C. Packaged CSRNet references cover all four datasets at FP32, FP16, and INT8 (`--precision`). They apply only to the full test split with all 23 corruptions at all three severity levels; partial runs are scored without the packaged mCE reference.

Use `--cells cells.csv` to export per-corruption, per-severity metrics.

## Reproducibility

Severity parameters are shared across datasets. Per-image randomness is seeded by `(image ID, corruption, severity, seed)`; fixed sensor patterns use `(dataset, corruption, severity, seed)`. The `structured_foreground_occlusion` layout depends only on `(image ID, severity)` and ignores `--seed`.

On the same machine, with identical inputs and software, outputs are byte-identical across runs and worker counts. Cross-machine results may vary:

- Floating-point differences may affect most corruptions slightly.
- Small differences in photon expectations for `low_light` can alter subsequent Poisson noise draws within an image band, producing larger pixel differences.
- Depth-dependent corruptions depend on cached depth maps, which can vary by GPU hardware and library versions.

Use `requirements-lock.txt` and the same depth maps when comparing builds. Every `manifest.json` records parameters, seeds, library versions, and SHA-256 file hashes.
